# データの形の版と移し替え

メモの記録（Yjs の文書）と本文の形は、アプリのバージョンが上がると変わることがあります。変わったデータを古いアプリが開くと、古いアプリのエディタは知らないノードを本文から消し、その削除が同期でほかのデバイスへ広がります。これを防ぐために、データの形に版を付け、古いアプリには新しい形のデータを読み書きさせません。

## 版の置き場所

- 版の数は `src/core/format/dataFormat.ts` の `DATA_FORMAT_VERSION` です。版ごとに何を変えたかも、同じファイルに書きます。
- vault ごとの版は、vault.json の項目 `bodySchema` に持ちます。手元（IndexedDB の設定 `vault`）と同期先（`<フォルダ>/vault.json`）の両方にあります。
- 項目の名前は、v0.5.0 までの「本文の形の版」のときのまま変えません。v0.5.0 までのアプリはこの名前の数を読んで止まるので、名前を変えると、古いアプリが新しい形のデータを書き換えてしまいます。

## 古いアプリを止める所

アプリが扱える版より、保存されている版の方が大きければ、`AppUpdateRequiredError` で止めて更新を求めます。確かめる所は次のとおりです。

| 場面 | 確かめるもの | 場所 |
|---|---|---|
| ロックの解除、スペースの切り替え | 手元の vault.json の版。記録を読む前に確かめる | `vault/vaultSession.ts` の `assembleUnlockedVault` |
| ほかのデバイスに参加する（同期の設定の取り込みも同じ） | 同期先の vault.json の版。手元に何も書かないうちに確かめる | `vault/vaultSession.ts` の `joinExistingVault` |
| 同期の 1 回ごと | 始めに同期先の vault.json の版を確かめる。記録を取ってきたら、手元へ入れる前に、取ってきた束（50 件）ごとに読み直す | `sync/syncEngine.ts` |
| バックアップから戻す | バックアップの中の vault の版 | `backup/vaultBackup.ts` |

同期の途中で読み直すのは、始めに確かめたあとで、新しいアプリが版を上げて新しい形の記録を送ることがあるためです。新しいアプリは、新しい形の記録を送る前に同期先の版を上げるので、記録を取ってきたあとに版を読み直せば、取ってきた記録が新しい形かどうかが分かります。

## 版を上げる

1. 次のどれかに当たるとき、`DATA_FORMAT_VERSION` を 1 つ上げ、何を変えたかを `dataFormat.ts` に書きます。
   - エディタが扱うノードや書式（`src/ui/editor/editorExtensions.ts`）を足した。`src/ui/editor/documentSchema.test.ts` が落ちるので気づけます。
   - 記録の Yjs の文書の中身の決まりを変えた。
   - 古いアプリに書かせたくない書き方をやめた（例: 版 14 の y-tiptap）。
2. 手元の記録を新しい形にする必要があれば、`src/core/format/dataFormatMigrations.ts` に手順を足します。
3. 1 回のリリースの中では、版は 1 つだけ上げます（版を上げるたびに、古いアプリが止まるため）。

## 移し替えの手順

手元の vault の版がアプリより古ければ、ロックを解除して記録を読み込んだあとに、`dataFormatMigrations.ts` の手順を版の古い順に流し、全部が済んでから手元の版を上げます（`vault/vaultSession.ts` の `migrateLocalDataFormat`）。同期先の vault.json の版は、次の同期の始めに上げ、そのあとで書き換えた記録を送ります。

手順を書くときの決まり:

- 何度流しても同じ結果になるように書きます。途中で止まったら、次の解除でもう一度流れます。2 つのウィンドウが同時に流すこともあります。
- 記録の文書は、利用者の編集として扱わない変更（`NoteRepository.migrateRecords`）で書き換えます。メモの更新日時は変わらず、履歴も残りません。書き換えた記録は、同期先へ送る記録になります。
- 読む側は、古い形の記録も読めるようにしておきます。版を上げる前に古いアプリが送った記録は、あとから届くことがあります。

## 同じデバイスの、ほかのウィンドウ

Web 版は、古いバージョンのタブを開いたまま、新しいバージョンを別のタブで開けます。新しいアプリが手元のデータを移し替えると、ほかのウィンドウへ合図（`dataFormatAdopted`）を送ります。受け取ったウィンドウは、自分の扱える版より新しければ、まだ保存していない入力を書いてから読み込み直し、新しいバージョンで開き直します（`ui/session/useVaultSession.ts`）。

この合図を知っているのは、版 14 からのアプリです。v0.5.0 までのアプリのタブは合図を無視しますが、同期先の版が上がった時点で同期を止めます。
