# 重ねて出すもの・モードを足すときの完了条件

ダイアログ・メニュー・候補の一覧・文字を選んだときのボタンの並び・AI チャットの欄・メモの中の検索のバーのように、画面の上に重ねて出すものと、ズーム・フォーカスモードのように画面の出し方を切り替えるモードは、作ったあとに「Esc で戻れない」「戻るボタンが無い」「項目が多いと崩れる」といった指摘を受けて直すことを繰り返してきました（ズームの Esc と戻るボタン、フォーカスモードの戻るボタン、メニューの高さの上限）。

新しく足すときは、次の項目を全部満たしたら完成とします。満たせない項目は理由を同じ変更の中（コミットの本文か、この文書の「例外」）に書きます。

## 完了条件

1. Esc で閉じる・戻るようにします。重ねて出すものは Esc で閉じ、モードは Esc で 1 段戻ります。Esc を誰が使うかは `src/ui/shared/escapeOwners.ts` にまとめてあり、入力欄・ダイアログ・メニューが開いている間は、そちらが Esc を使います。新しいものもここに足し、ほかの Esc（ズームから戻る、フォーカスモードを終わる）と取り合わないようにします。
2. モードには左上に戻るボタンを 1 つ置きます。ズーム（`ZoomBackButton.tsx`）とフォーカスモード（`.focus-mode-exit`）と同じ位置・同じ部品にします。キーを知らない人もボタンで戻れるようにするためです。
3. 開いた直後と閉じた直後に打った文字が、正しい所に入るようにします。開いたら入力欄（無ければ最初の項目）にフォーカスを移し、閉じたら開く前の所（本文ならカーソルの位置ごと。`src/ui/shared/focusReturn.ts`）へ戻します。フォーカスが body に落ちると、続けて打った文字がどこにも入りません。画面の試験で、開いた直後と閉じた直後に文字を打って確かめます。
4. 項目が 100 件あっても、枠の中に収まるようにします。メニューと候補の一覧は、開く向きの空きに高さを合わせ、中で送ります（`PopupMenu.tsx` の `placeMenu`）。「/」のメニューにはスクロールバーを出しません（利用者の決定）。低い窓（高さ 520px）でも窓の外へ出ないことを、見た目の検査（下記）で確かめます。
5. スマホにも入口を置きます。スマホでも同じ機能を使えるようにします。PC だけにするなら、その理由を書き、スマホに無い機能の一覧（引き継ぎの記録）に足します。
6. 戻せない操作には確認か「元に戻す」を付けます。重ねて出したものから削除・上書き・結合などを行うときは、確かめるダイアログ（`DialogProvider` の `confirm`）か、「元に戻す」つきの知らせ（`ToastProvider`）を出します。

## 足したら同じ変更で行うこと

- 見た目の検査の画面の一覧に足します。`scripts/app-checks/visualConsistency/auditScreens.mjs`（AI は `aiChatScreens.mjs`、同期は `syncScreens.mjs`、低い窓は `lowWindowScreens.mjs`）に、開き方と閉じ方を足します。道具で開けない状態は理由を付けて `UNVISITED_STATES` に書きます。撮っていない状態があると、見た目の不ぞろいを見落とします（モデルの選択欄が四角いままだったのは、モデルの一覧を取ったあとの状態を撮っていなかったため）。
- 設定に欄を足したら、`src/ui/settings/settingsSearchEntries.ts` にも足します。
- 画面の試験を足します。試験の名前は振る舞いを書きます（「〜すると〜になる」）。Esc・戻るボタン・開いた直後と閉じた直後の入力を、少なくとも 1 つずつ確かめます。

## 確かめ方

```sh
npx vite --host 127.0.0.1 --port 5173 --strictPort
BASE_URL=http://127.0.0.1:5173/ node scripts/app-checks/visualConsistency/auditVisualConsistency.mjs <結果を置くフォルダ>
```

結果の `report.md` の「指摘」が増えていないことを確かめます。指摘には、ずれ・はみ出しのほか、次のものも数えます。

- 同じ役割の部品（入力欄・選択欄・メニューの項目・タブなど）で角丸や高さが割れている所。意図した違いは `auditExceptions.mjs` に理由つきで書きます。理由が書けない違いは直します。
- 入力欄の行が入れ物の右の端まで届いていない所、閉じる「×」が行の右の端に無い所（`measureContainerFit.mjs`）。
- メニュー・ダイアログが窓の外へはみ出している所。
- 英語の画面に残った日本語。

「開けなかった画面」が 0 件であることも確かめます。新しい画面を道具に足すときは、部品を文言で探さずに済むなら role・クラス名で探し、文言で探すときは `scripts/app-checks/appMessages.mjs` の `translate` でアプリの文言をキーから引きます（文言を道具に書き写すと、画面の言い換えで開けなくなります）。

狭い幅・スマホ・ダークのテーマ・最悪のデータ（多い・長い・空・絵文字）でも流します。

```sh
DESKTOP_SIZE=1100x820 … auditVisualConsistency.mjs <フォルダ>   # 狭い PC
PHONE_SIZE=360x640 … auditVisualConsistency.mjs <フォルダ>       # 小さいスマホ
THEME=ダーク … auditVisualConsistency.mjs <フォルダ>
DATA=worst … auditVisualConsistency.mjs <フォルダ>               # ノートブック 80、メモ 500、タグ 100、長い題、列の多い表など
```

## 例外

今のところ、満たしていない項目は次のとおりです。

- 文字を選んだときのボタンの並びは、Esc でボタンだけを消し、選択は残します（選択をやめるのは、本文を押すか矢印のキー）。
- タブ・コマンドパレット・画面分割・別ウィンドウ・フォーカスモードは、スマホには置いていません（スマホは 1 画面に 1 つのメモを出す形のため）。
