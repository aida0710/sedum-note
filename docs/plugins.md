# プラグインの仕様

Sedum Note のプラグインは、メモの「…」のメニューにコマンドを足します。この文書は、プラグインの置き方、宣言の書き方、モジュールの決まり、入力と出力、できることの範囲を決めたものです。形式の版は 1 です。

見本は、このリポジトリの [`plugins/text-tools`](../plugins/text-tools) にあります。

## できることの範囲

プラグインは、利用者がコマンドを選んだときにだけ動きます。そのとき、開いているメモのうち、宣言で「読む」としたものを受け取り、書き換えの指示を返します。アプリは、返ってきた指示のうち、宣言で「書く」としたものだけを実行します。

プラグインにできないことは、次のとおりです。

- 通信（プラグインから外へは、何も送れません）
- 保存（実行をまたいで、何も覚えておけません）
- 開いているメモのほかのメモ、添付の中身、設定、鍵を読むこと
- 画面を描くこと、時刻を知ること、乱数を得ること
- 利用者が選んでいないときに動くこと

これは、プラグインを「外の関数を何も取り込まない WebAssembly のモジュール」に限ることで守ります。アプリは、モジュールに何も渡さずに組み立てるので、モジュールが使えるのは、自分のメモリと計算だけです。JavaScript のプラグインはありません。

プラグインが本文に書いた文字には、気を付けてください。プラグインは通信できませんが、プラグインが本文にリンクを書き、利用者がそれを押せば、その先へはつながります。外の画像や動画の埋め込みは、プラグインが書いても、リンクの文字として入るだけで、開いただけでは読み込みません。

## 置き方と取り込み

プラグインは、GitHub のリポジトリのフォルダに、次の 2 つを置いたものです。

| ファイル | 中身 |
|---|---|
| `sedum-note-plugin.json` | 宣言 |
| 宣言の `module` に書いたファイル（`.wasm`） | 組み立て済みの WebAssembly のモジュール |

フォルダは、リポジトリの直下でも、その下のフォルダでも構いません。1 つのリポジトリに、いくつものプラグインを置けます。

利用者は、「設定」の「プラグイン」に取り込み元を入れて取り込みます。取り込み元の書き方は 2 つです。

```
所有者/リポジトリ[/フォルダ][@タグ・ブランチ・コミット]
https://github.com/所有者/リポジトリ[/tree/タグ・ブランチ/フォルダ]
```

例:

```
aida0710/sedum-note/plugins/text-tools
someone/sedum-note-plugin@v1.2.0
https://github.com/someone/plugins/tree/main/word-count
```

アプリは、取り込むときに次の順に行います。

1. タグやブランチの名前を、その時点のコミット（40 桁の SHA）に直す（`api.github.com` の `GET /repos/{所有者}/{リポジトリ}/commits/{名前}`。名前を省いたら、既定のブランチ）。コミットの SHA を指定したときは、聞かない。
2. そのコミットの `sedum-note-plugin.json` と、モジュールを読む（`raw.githubusercontent.com`）。
3. 宣言とモジュールが、この文書の決まりに合うかを確かめる。合わなければ、取り込まない。
4. プラグインの名前・読むもの・書くもの・足すコマンド・コミット・モジュールの SHA-256 を、利用者に見せる。利用者が「入れる」を押したら、入れる。

入れたプラグインは、そのコミットのものに固定されます。取り込み元が書き換えられても、アプリの中のプラグインは変わりません。利用者が「更新を確かめる」を押したときだけ、取り込み元の今のコミットを確かめ、変わっていれば、できることを見せ直してから入れ替えます。

GitHub へつなぐのは、取り込むときと、「更新を確かめる」を押したときだけです。認証情報も、アプリや利用者を見分ける値も送りません。認証なしの GitHub の API は、同じ IP アドレスから 1 時間に 60 回までです。

入れたプラグインは、マスターキーで暗号化して、そのデバイスのそのスペースに置きます。同期とバックアップには入りません。実行の前に、モジュールが取り込んだときのものと同じかを、SHA-256 で確かめます。

## 宣言（sedum-note-plugin.json）

```json
{
  "formatVersion": 1,
  "id": "text-tools",
  "name": "Text tools",
  "version": "1.0.0",
  "description": "Sorts the selected lines, removes duplicate lines, and counts the characters of the note.",
  "author": "Sedum Note",
  "module": "text-tools.wasm",
  "reads": ["note.selection", "note.body"],
  "writes": ["note.selection", "message"],
  "commands": [
    { "id": "sort-lines", "title": "Sort the selected lines", "description": "Sorts the lines of the selection in ascending order." }
  ]
}
```

| 項目 | 必須 | 決まり |
|---|---|---|
| `formatVersion` | はい | `1`。ほかの値の宣言は、取り込まない |
| `id` | はい | プラグインを見分ける名前。小文字・数字・ハイフンの 2〜64 文字で、ハイフンでは始めない。同じ `id` のプラグインを取り込むと、入れ替える |
| `name` | はい | 画面に出す名前。200 文字まで |
| `version` | はい | 画面に出すバージョン。書き方は自由。200 文字まで |
| `description` | いいえ | 画面に出す説明。200 文字まで |
| `author` | いいえ | 画面に出す作者。200 文字まで |
| `module` | はい | モジュールの場所。宣言と同じフォルダからの相対パスで、`.wasm` で終わる。使える文字は、英数字と `.` `_` `-` と、フォルダの区切りの `/`。上のフォルダ（`..`）は指せない |
| `reads` | いいえ | プラグインが読むもの（下の表）。省くと、何も読まない |
| `writes` | いいえ | プラグインが書くもの（下の表）。省くと、何も書かない |
| `commands` | はい | 足すコマンド。1〜50 個。`id` は、プラグインの `id` と同じ決まりで、プラグインの中で重ならない。`title` は必須、`description` は任意（どちらも 200 文字まで） |

名前や説明は、書いたとおりに画面に出します（アプリは訳しません）。

### 読むもの（reads）

| 値 | 渡すもの |
|---|---|
| `note.title` | 開いているメモの題 |
| `note.body` | 開いているメモの本文（Markdown） |
| `note.selection` | 選択した文字（書式なし。段落や項目の区切りは、改行 1 つ）。選択していなければ空 |

### 書くもの（writes）

| 値 | 実行する指示 | すること |
|---|---|---|
| `note.selection` | `replaceSelection` | 選択した文字を置き換える。選択していなければ、カーソルの所に入れる |
| `note.body` | `replaceBody` | 本文の全部を置き換える。置き換える前の状態は、メモの履歴に残る |
| `note.append` | `append` | 本文の末尾に足す |
| `note.title` | `setTitle` | 題を変える |
| `message` | `message` | 短い知らせを出す |

宣言に無い指示を返しても、アプリは実行しません。宣言に無いものは、入力にも入りません。

## モジュール

モジュールは、WebAssembly のバイナリ（`.wasm`）です。決まりは次のとおりです。

- **外の関数・メモリ・表・変数を、何も取り込まない**（import が 1 つでもあれば、取り込みを断る）。WASI や、ブラウザ向けのつなぎのコードを取り込むモジュールは使えません。Rust なら、ターゲットは `wasm32-unknown-unknown` です。
- 次の 3 つを、この名前で出す（export）。

| 名前 | 種類 | 決まり |
|---|---|---|
| `memory` | メモリ | モジュールのメモリ |
| `sedum_alloc` | 関数 `(i32) -> i32` | 引数のバイト数の入力を置ける場所を、`memory` の中に取り、その位置を返す |
| `sedum_run` | 関数 `(i32, i32) -> i64` | 引数は、入力の位置と長さ。コマンドを実行して、出力の位置と長さを 1 つの値で返す。上位 32 ビットが位置、下位 32 ビットが長さ |

- 大きさは 2 MiB まで。
- 入力と出力は、UTF-8 の JSON（下の章）。どちらも 4 MiB まで。

アプリは、コマンドを実行するたびに、モジュールを新しく組み立てます。前の実行で書いたメモリは、次の実行には残りません。実行は、画面とは別のスレッドで行い、5 秒で終わらなければ止めます。

実行の流れは、次のとおりです。

1. アプリが `sedum_alloc(入力の長さ)` を呼び、返ってきた位置に、入力を書く。
2. アプリが `sedum_run(入力の位置, 入力の長さ)` を呼ぶ。
3. アプリが、返ってきた位置と長さの範囲を、出力として読む。範囲がメモリの外なら、失敗にする。

## 入力と出力

### 入力

```json
{
  "formatVersion": 1,
  "command": "sort-lines",
  "locale": "ja",
  "note": {
    "title": "買い物",
    "markdown": "牛乳\n\n卵",
    "selection": "みかん\nりんご"
  }
}
```

| 項目 | 中身 |
|---|---|
| `formatVersion` | `1` |
| `command` | 利用者が選んだコマンドの `id` |
| `locale` | 画面の言語（`ja` か `en`）。知らせの文を出し分けるのに使える |
| `note.title` | 宣言の `reads` に `note.title` があるときだけ入る |
| `note.markdown` | 宣言の `reads` に `note.body` があるときだけ入る |
| `note.selection` | 宣言の `reads` に `note.selection` があるときだけ入る |

本文の Markdown は、アプリが Markdown で書き出すときと同じ形です。添付は `sedum-note://attachment/<ID>` へのリンク、ほかのメモへのリンクは `sedum-note://note/<ID>` へのリンクで表します。

### 出力

```json
{
  "replaceSelection": "みかん\nりんご",
  "message": "2 lines sorted"
}
```

| 項目 | 中身 |
|---|---|
| `replaceSelection` | 選択と置き換える文字。Markdown としては読まない。1 行ならその行の途中に入れ、2 行以上なら、行ごとに段落にする |
| `replaceBody` | 本文の全部と置き換える Markdown |
| `append` | 本文の末尾に足す Markdown |
| `setTitle` | 新しい題 |
| `message` | 利用者に見せる短い知らせ（500 文字まで。超えた分は切る） |
| `error` | 実行できなかった理由。これがあると、アプリはほかの指示を実行せず、失敗として知らせる |

どの項目も省けます。何もしないなら、`{}` を返します。

`replaceBody` と `append` の Markdown は、アプリが Markdown を取り込むときと同じ決まりで読みます。添付のリンク（`sedum-note://attachment/<ID>`）は、利用者のメモにもう貼ってある添付だけを指せます。外の画像（`![…](https://…)`）は、リンクの文字になります。行の末尾の ` ^ID`（ブロックの ID）を残すと、そのブロックを指しているリンクが切れません。

## プラグインを作る

見本の [`plugins/text-tools`](../plugins/text-tools) は、Rust で書いてあります。

```sh
rustup target add wasm32-unknown-unknown
cd plugins/text-tools
cargo build --release --target wasm32-unknown-unknown
cp target/wasm32-unknown-unknown/release/sedum_note_text_tools.wasm text-tools.wasm
```

組み立てた `.wasm` を、宣言と同じフォルダに置いてコミットします（アプリは、プラグインを組み立てません）。

外の関数を取り込んでいないかは、次のように確かめられます。

```sh
node -e 'WebAssembly.compile(require("fs").readFileSync("text-tools.wasm")).then((m) => console.log(WebAssembly.Module.imports(m)))'
```

`[]` が出れば、取り込みはありません。時刻や乱数、標準入出力を使うと、多くの道具は外の関数を取り込むモジュールを作ります。そのモジュールは、アプリが断ります。

## 形式の版

この文書の形式の版は 1 です。入力・出力・宣言の項目を足すだけの変更では、版を上げません。プラグインは、知らない入力の項目を読み飛ばしてください。アプリは、知らない出力の項目と、知らない宣言の項目を読み飛ばします。今のプラグインが動かなくなる変更をするときに、版を上げます。
