# 暗号化のしくみ

Sedum Noteはメモをデバイスの中で暗号化してから保存し、同期します。同期先の管理者が見られるのは、暗号化されたデータと、その件数・大きさ・更新日時などだけです。

## キーの構成

- メモと添付は、ランダムなマスターキー（AES-256）で暗号化します。
- マスターキーは置き場所ごとに別の秘密からArgon2id（64MiB、3回）で作ったキーで包みます。デバイスの中では、そのデバイスのパスフレーズで包みます。同期先の`vault.json`では、暗号化キーで包みます。
- パスフレーズと、パスフレーズで包んだものは、同期先に置きません。
- メモと添付は、1件ごとにAES-256-GCMで暗号化し、記録のIDを追加認証データに入れます。同期先の上で暗号文を別のIDに入れ替えても、開けません。
- 同期先の認証情報もマスターキーで暗号化してデバイスの中に保存します。

ロックを解除したウィンドウは、マスターキーをメモリにだけ持ちます。別のウィンドウをパスフレーズなしで開くときは、そのウィンドウに頼まれてから、マスターキーを取り出せない形（CryptoKey）のまま渡し、どこにも保存しません。PCのアプリではアプリのウィンドウの間（BroadcastChannel）で渡します。Web版のページのorigin（github.io）はほかのページと共有なので、BroadcastChannelは使わず、アプリが開いた別のウィンドウと元のウィンドウの間でだけ、相手のウィンドウへ直接（postMessage）渡します。受け取ったウィンドウは、そのマスターキーが手元のvaultのものかを確かめてから開きます。

## 同期先に置くもの

| オブジェクト | 中身 |
| --- | --- |
| `<フォルダ>/vault.json` | 暗号化キーで包んだマスターキーと、Argon2idの値 |
| `<フォルダ>/records/<ID>` | メモ・ノートブック1件の暗号文 |
| `<フォルダ>/blobs/<ID>` | 画像などの添付1件の暗号文 |
| `<フォルダ>/versions/<メモのID>/<バージョンのID>-<残した時刻の暗号文>` | メモの履歴1件の暗号文 |

IDはランダムで、タイトルやノートブックの名前は同期先から読めません。履歴のオブジェクトの名前には、古い履歴を一覧だけで見分けて削除できるよう、残した時刻を入れています。時刻はマスターキーで暗号化してあり、同期先からは読めません。

## 暗号化しないもの

次のものは暗号化しません。

- 「設定」の「データ」でエクスポートしたMarkdownなどのファイル
- 期限の通知の文。Androidでは、期限の時刻に通知を出せるよう、メモのタイトルと項目の文をOSに預けます
- このデバイスの表示の設定（テーマや並び順など）と、スペースの名前

## 外部に送るデータ

| 送る先 | 送るもの |
| --- | --- |
| 同期先 | 暗号化したメモ・添付・履歴 |
| AIの接続先（設定したときだけ） | 会話の内容と、AIに渡したメモ・AIが読んだメモの本文。暗号化されません（[AIチャット](/ai/chat)） |
| GitHub | 更新の確認のときに、アプリのバージョンとOSの種類。プラグインを入れる・更新するときは、プラグインのファイルを取得します |
| 埋め込んだページや動画のサイト | 「読み込む」を押したときの、アクセスの情報（IPアドレスなど） |

使い方の記録や統計、エラーの報告を集めて送ることはしません。
